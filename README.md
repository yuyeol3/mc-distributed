# mcd

**상시 서버 없이 친구들과 하나의 마인크래프트 월드를 공유하는 프로그램.**

서버 비용을 내거나 누군가 서버를 계속 켜 둘 필요가 없다. 플레이하려는 사람의 PC가 그때그때 서버가 되고, 월드는 GitHub private repo에 버전으로 보관된다. 오늘은 내가 혼자 건축하고, 내일은 친구가 혼자 들어와도 같은 월드가 이어진다.

- **누가 먼저 켜든 최신 월드**: 접속하는 사람의 PC가 서버가 되고, 마지막으로 저장된 월드에서 시작한다.
- **주소는 항상 `localhost:25565`**: 누가 호스트인지 몰라도 된다. mcd가 알아서 이어준다.
- **호스트가 나가도 계속 플레이**: 다른 사람이 접속해 있으면 서버가 그 사람 PC로 자동으로 옮겨 간다.
- **월드가 갈라지지 않음**: 동시에 두 명이 켜도 서버는 하나만 뜨고, 크래시가 나도 자동으로 복구된다.
- **친구는 설치할 것이 없음**: 인터넷 너머의 친구와도 mcd 하나로 연결된다(VPN이나 포트 포워딩이 필요 없음).

어떻게 동작하는지는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)(다이어그램 포함), 진행 상황은 [docs/PLAN.md](docs/PLAN.md)에 있다.

## 준비물

| 무엇 | 누가 | 비고 |
|---|---|---|
| Windows 10/11 PC | 모두 | 배포판은 Java 런타임을 포함하므로 Java를 설치하지 않아도 된다 |
| 마인크래프트 Java Edition (월드의 버전) | 모두 | 새 월드는 26.2로 만들어진다. 월드 주인이 버전을 올리면 모두 그 버전으로 맞춘다. mcd 창에 "이 월드는 마인크래프트 OOO용입니다"가 뜬다. 정품 계정이 필요하다 |
| GitHub 계정 | 월드 주인만 | 월드를 보관하는 곳이다. **메인 계정과 따로 만든 계정**을 권한다(아래 참고). 친구는 GitHub 계정이 필요 없다(초대 코드로 참가) |
| Tailscale 계정 | 월드 주인만 | 인터넷 너머의 친구와 할 때만 필요하다. 친구는 필요 없다 |

GitHub 토큰은 필요 없다. 월드마다 mcd가 만든 **deploy key**(그 repo 하나에만 쓰는 SSH 키)를 월드 주인이 GitHub 웹에서 한 번 등록하고, 친구는 그 키가 든 **초대 코드**로 참가한다.

**Tailscale 인증 키 만들기**(월드 주인): [Tailscale 관리 화면](https://login.tailscale.com/admin/settings/keys) → Settings → Keys → Generate auth key. **Reusable**을 켜서 만든다. 이 키는 월드 repo에 저장돼 친구들에게 자동으로 전달되므로, 친구들은 Tailscale에 가입하지 않는다.

## 빠른 시작

### 월드 주인

1. `mcd-windows.zip`을 풀고 `mcd/mcd.exe`를 실행한다.
2. 처음 설정 창에서 **내 이름**(다른 사람에게 보일 이름)을 넣고 **Minecraft EULA 동의**에 체크한다. GitHub 토큰은 비워 둔다.
3. [github.com/new](https://github.com/new)에서 **빈 private repo**를 만든다(README 등 초기 파일 없이).
4. 이어서 나오는 월드 추가 창에서 다음을 넣는다.
   - **새 월드 만들기**를 고르고 방금 만든 repo 주소를 넣는다.
   - **tailnet 인증 키**: 인터넷 너머의 친구와 할 거라면 Tailscale 인증 키를 넣는다. 같은 집에서만 할 거면 비워 둔다.
5. 추가를 누르면 deploy key 등록 안내가 뜬다. 'GitHub에서 열기'로 repo의 Deploy key 추가 화면을 열고, Title `mcd`, Key에 안내 창의 공개키를 붙여 넣은 뒤 **Allow write access**를 체크하고 Add key. mcd에서 '등록 완료'를 누르면 접속을 확인하고 월드를 올린다.
6. mcd 창의 **친구 초대**를 누르면 초대 코드가 복사된다. 친구에게 보낸다.
7. 마인크래프트 → 멀티플레이 → 서버 추가 → 주소 **`localhost:25565`** 로 접속한다.

초대 코드를 가진 사람은 누구나 월드를 읽고 쓸 수 있다. 공개된 곳에 올리지 않는다. 초대를 끊으려면 **친구 초대 → 키 바꾸기**로 새 키를 등록한 뒤, GitHub repo의 Settings → Deploy keys에서 예전 mcd 키를 지운다(계속 함께할 친구에게는 새 코드를 보낸다).

### 친구

1. `mcd/mcd.exe`를 실행하고 처음 설정(이름, EULA)을 마친다. GitHub 계정과 토큰은 필요 없다.
2. 월드 추가 창에서 **친구의 월드에 참가**를 고르고 받은 **초대 코드**(`mcd1.`로 시작)를 붙여 넣는다. tailnet 인증 키는 비워 둔다(월드에 이미 들어 있다).
3. 마인크래프트에서 **`localhost:25565`** 로 접속한다.

예전 방식(repo collaborator로 초대받고 GitHub 토큰으로 접속)으로 추가한 월드도 그대로 쓸 수 있다. 그 월드에서 **친구 초대**를 누르면 deploy key 등록을 안내하고, 등록하면 그 PC도 키로 접속하도록 바뀐다.

### 플레이할 때 일어나는 일

- **아무도 없을 때 접속하면** 내 PC가 서버가 된다. mcd 창에 "이 PC가 호스트가 됐습니다"가 뜨고, 서버가 뜰 때까지 접속 중 화면에서 기다렸다가 들어간다(보통 10~20초). 서버 파일(Mojang jar 받기와 패치)은 mcd가 월드를 열 때 미리 준비하므로, 그 PC에서 처음 서버가 될 때도 더 걸리지 않는다. 대신 월드를 처음 열 때 20초 안팎이 더 걸린다.
- **서버 목록을 열기만 해서는** 서버가 뜨지 않는다. 아무도 없으면 목록에 "mcd: 접속하면 서버가 시작됩니다"가 보인다.
- **누가 이미 플레이 중이면** 그 사람의 서버로 이어진다. mcd 창에 "지금 호스트는 OOO입니다"가 뜬다.
- **호스트가 mcd를 끄면** 남은 사람들은 잠깐 로딩 화면을 본 뒤 자동으로 다른 사람의 PC로 옮겨 간다.
- **모두 나가면** 5분 뒤 서버가 스스로 월드를 GitHub에 올리고 꺼진다.
- **플레이 중에도** 10분마다 월드가 GitHub에 올라간다.
- **mcd 창을 닫으면** 월드를 저장하고 올린 뒤 끝난다. 그냥 닫으면 된다.
- **새 버전이 나오면** mcd를 켤 때 업데이트할지 물어본다. 동의하면 받아서 검증한 뒤 mcd를 껐다가(호스트였다면 평소처럼 저장하고 넘김) 바꾼 다음 다시 켠다. 같은 월드를 쓰는 친구들끼리는 버전을 맞추는 게 좋다.

### mcd 창에서 할 수 있는 것

창 가운데의 상태 카드에 지금 상태(호스트 없음, 지금 호스트가 누구인지, 이 PC가 서버를 띄우는 중, 이 PC가 호스트이고 접속 몇 명)와 마인크래프트에서 접속할 주소가 나온다. 테마는 Windows의 앱 모드(라이트/다크)를 따른다.

| 버튼 | 하는 일 |
|---|---|
| **월드** 목록 | 여러 월드를 오갈 수 있다. 다른 월드를 고르면 지금 월드를 저장하고(호스트였다면 접속 중인 사람에게 넘기고) 고른 월드로 바꾼다 |
| **월드 추가** | 새 월드를 만들거나 친구의 월드에 참가한다 |
| **목록에서 빼기** | 지금 월드를 목록에서 뺀다. GitHub의 월드와 이 PC의 사본은 지우지 않으므로 다시 추가할 수 있다 |
| **버전 올리기** | 지금 월드의 마인크래프트(Paper) 버전을 올린다. 누가 플레이 중이면 안 되고, 되돌릴 수 없다. 모두 그 버전의 마인크래프트로 접속해야 한다 |
| **친구 초대** | 지금 월드의 초대 코드를 복사한다. 월드에 deploy key가 없으면 등록을 먼저 안내한다. **키 바꾸기**로 지금까지의 초대를 끊을 수 있다 |
| **설정** | 내 이름, GitHub 토큰(예전 방식 월드에만), 내 서버 주소를 바꾼다. 토큰을 넣으면 GitHub에 확인한 뒤에 저장한다 |
| **로그와 Paper 콘솔** | 펼치면 mcd와 Paper의 로그가 보이고, 이 PC가 호스트일 때 Paper 명령(예: `op <이름>`)을 보낼 수 있다 |
| **월드·플러그인 관리** | 월드 폴더·ZIP 교체, 변경 전 백업 복구, 플러그인 JAR 추가·교체·제거 |

## 월드 교체와 플러그인 관리

메인 창의 **월드·플러그인 관리**를 연다. 호스트가 실행 중이면 변경을 거절한다. 플레이를 끝낸 뒤 호스트의 Paper 콘솔에서 `stop`으로 서버를 종료하거나, 빈 서버가 스스로 종료할 때까지 기다린다. 관리 작업 중에는 다른 PC에서도 호스팅을 시작할 수 없다.

- **월드 교체**: 실행 중이지 않은 Vanilla/Paper 월드 폴더 또는 ZIP을 선택한다. 버전과 교체 범위를 확인한 뒤 적용한다. 오버월드·차원·플레이어 데이터를 교체하고 서버 설정·플러그인·초대 정보는 유지한다. 현재 Paper보다 새 월드와 모드 전용 월드는 지원하지 않는다. 기본 `level-name=world`를 사용해야 한다. 싱글플레이 주인의 인벤토리를 서버 플레이어 파일로 자동 변환하지는 않는다.
- **백업 복구**: 관리 작업 전 상태는 원격 `backup/...` 브랜치에 보관한다. 선택한 백업의 월드·플러그인·운영 설정을 새 커밋으로 복원한다. 복원 직전 상태도 먼저 백업한다.
- **플러그인**: 신뢰하는 로컬 Paper/Bukkit JAR를 추가한다. 같은 이름의 플러그인은 교체하고, 제거 시 데이터 폴더는 보존한다. JAR도 Git으로 공유하며 호스트 시작 전에 파일 해시와 의존성을 검사한다. 배포 목록과 실제 활성 상태는 구분한다. 활성 여부는 호스트에서 **활성 목록(콘솔)**을 누르거나 `plugins` 명령으로 확인한다.

관리 작업은 별도 임시 사본에서 수행한다. 실패 메시지에는 백업 ID와 작업 사본 경로가 나온다. 미완성 파일을 사용하던 로컬 월드에 덮어쓰지 않는다. 플러그인의 SQLite·외부 DB·비동기 저장 데이터까지 무손실 이관을 보장하는 기능은 포함하지 않는다.

**모든 참가자의 mcd를 종료하고 새 버전으로 맞춘 뒤 시작한다. 이번 락 형식은 이전 앱과 혼용하지 않는다.** 옛 호스트의 health 정보가 없으면 기존 TTL 인수를 사용한다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 처음 접속할 때 "시간 초과"로 끊김 | mcd는 서버가 뜰 때까지(최대 3분) 접속을 붙잡아 둔다. 그래도 끊기면 다시 접속하면 된다(서버는 그사이에도 계속 뜬다) |
| "지금 호스트는 OOO"인데 접속이 안 됨 | 5초 간격 상태 확인이 3회 실패하면 응답 없음으로 표시한다. 재접속하면 락 인수 후 기존 writer 종료를 위해 30초 기다리고 새 서버를 띄운다. Paper 기동 시간은 별도다. health 정보가 없는 옛 호스트는 기존 TTL만 사용한다 |
| 접속 화면에서 버전이 맞지 않다고 나옴 | 마인크래프트 버전을 mcd 창에 뜨는 월드 버전으로 바꾼다 |
| "Java N 이상이 필요한데" | 월드가 이 mcd보다 새 Paper를 쓴다. mcd를 새 버전으로 바꾼다 |
| "이 키로 쓰지 못했습니다" (deploy key 등록) | 공개키를 끝까지 붙여 넣었는지, **Allow write access**를 체크했는지 확인한다. 등록할 repo가 안내 창 제목의 repo와 같은지 본다 |
| 친구가(또는 나도) 갑자기 접속하지 못함 | repo의 Deploy keys에서 mcd 키가 지워졌을 수 있다. 월드 주인이 **친구 초대 → 키 바꾸기**로 다시 등록하고 새 초대 코드를 보낸다 |
| "토큰을 확인하지 못했습니다" | 예전 방식 월드에만 해당. 토큰이 틀렸거나 `repo` 권한이 없다 |
| "원격에 올리지 못했습니다" (새 월드) | repo가 비어 있지 않다(README 등). 빈 repo를 새로 만든다 |
| 토큰이나 이름을 바꾸고 싶음 | mcd 창의 **설정** |
| 설정을 처음부터 다시 하고 싶음 | `%USERPROFILE%\.mcd\settings.properties`를 지우고 다시 실행한다 |
| GitHub repo에 `recovery/...` 브랜치가 생김 | PC가 갑자기 꺼진 사이 다른 사람이 이어서 플레이해서, 꺼졌던 PC의 마지막 몇 분이 따로 보관된 것이다. 메인 월드는 갈라지지 않았다. 필요 없으면 지워도 된다 |
| Windows 방화벽 허용 창이 뜸 | mcd와 함께 도는 Java(Paper)나 `mcd-net`이 네트워크를 쓰려는 것이다. 허용한다 |

## CLI 사용법

배포판의 `mcd/mcd-cli.exe`(또는 직접 빌드한 `build/install/mcd/bin/mcd`)로 GUI 없이 쓸 수 있다. deploy key로 접속하려면 `--deploy-key <파일>`(키 문자열이 든 파일)과 SSH 원격 주소(`ssh://git@ssh.github.com:443/<계정>/<repo>.git`)를 쓴다. 그렇지 않으면 GitHub 토큰을 환경 변수 `MCD_GITHUB_TOKEN`으로 넘긴다.

```sh
# 새 월드 만들기 (원격 repo는 비어 있어야 한다)
mcd-cli init --remote https://github.com/<계정>/<repo>.git --dir worlds/survival --tailnet-auth-key <키>

# 노드 띄우기: 이후 마인크래프트에서 localhost:25565로 접속한다
mcd-cli play --remote https://github.com/<계정>/<repo>.git --dir worlds/survival --node <내 이름> --accept-eula
```

```sh
# 월드의 마인크래프트(Paper) 버전 올리기: 모두 나간 상태에서
mcd-cli upgrade-paper --remote https://github.com/<계정>/<repo>.git --dir worlds/survival --node <내 이름> --paper 26.2
```

`play` 중 콘솔 입력은 내 PC가 호스트일 때 Paper 콘솔로 넘어간다(예: `op <이름>`, `difficulty hard`). `stop`이나 Ctrl+C를 누르면 저장하고 끝난다.

| 명령 | 옵션 | 설명 |
|---|---|---|
| `init` | `--remote <git URL>` | 비어 있는 원격 repo |
| | `--dir <폴더>` | 월드를 둘 새 폴더 |
| | `--paper <버전 또는 버전-빌드>` | 월드의 마인크래프트(Paper) 버전. 없으면 기본값(26.2-133), 버전만 주면 그 버전의 최신 안정 빌드 |
| | `--tailnet-auth-key <키>` | 인터넷 너머 친구와 하려면. 월드에 기록돼 모두에게 전달된다 |
| | `--tailnet-control-url <주소>` | 조정 서버. 비우면 Tailscale. Headscale을 직접 운영하면 그 주소 |
| | `--offline` | online mode를 끈다(테스트용, 정품 인증 없음) |
| `play` | `--remote`, `--dir`, `--node <이름>` | 필수 |
| | `--deploy-key <파일>` | 토큰 대신 그 월드의 deploy key로 SSH 접속(`init`, `upgrade-paper`에도 쓸 수 있다) |
| | `--accept-eula` | [Minecraft EULA](https://aka.ms/MinecraftEULA)에 동의 |
| | `--listen <포트>` | 마인크래프트가 접속할 이 PC의 포트(기본 25565) |
| | `--port <포트>` | 이 PC가 호스트일 때 Paper 포트(기본 25566) |
| | `--address <호스트:포트>` | tailnet 없이 같은 네트워크에서 쓸 때 다른 PC가 내 Paper에 접속할 주소 |
| | `--cache <폴더>` | Paper jar를 받아 둘 곳(기본 `~/.mcd/cache`) |
| | `--ttl-seconds`, `--handoff-port` | 테스트용 |
| `update` | | 새 버전이 있으면 받아서 검증해 두고, 이 설치 폴더의 mcd가 모두 끝나면 바꾼다 |
| `upgrade-paper` | `--remote`, `--dir`, `--node` | 필수 |
| | `--paper <버전 또는 버전-빌드>` | 올릴 버전. 버전만 주면(예: `26.2`) 그 버전의 최신 안정 빌드. 호스트가 있는 동안은 안 되고, 옛 버전으로는 되돌릴 수 없다 |

관리 CLI는 `world replace --remote <주소> --source <폴더 또는 ZIP>`, `world backups --remote <주소>`, `world restore --remote <주소> --backup <ID>`, `plugin list --remote <주소>`, `plugin add --remote <주소> --file <JAR>`, `plugin remove --remote <주소> --name <이름>`을 제공한다. `--node <이름>`과 `--deploy-key <파일>`도 사용할 수 있다.

## 파일 위치

| 위치 | 내용 |
|---|---|
| `~/.mcd/settings.properties` | GUI 설정(이름, 토큰, 서버 주소, 월드 목록과 월드별 deploy key). 토큰과 키가 평문으로 저장된다 |
| `~/.mcd/worlds/<repo 이름>/` | 월드의 로컬 사본이자 Paper 서버 폴더(git 작업 트리) |
| `~/.mcd/cache/` | Paper jar(월드가 쓰는 빌드를 처음 쓸 때 받는다)와 검증한 해시(`.sha256`) |
| `~/.mcd/tailnet/` | tailnet 노드 키. 월드 폴더 밖에 둬서 GitHub에 올라가지 않는다 |

## 직접 빌드하기

필요한 것: JDK 25, Go(`mcd-net` 빌드), Node.js(E2E 테스트 봇).

```sh
./gradlew installDist      # build/install/mcd (JAVA_HOME이 Java 25여야 실행된다)
./gradlew packageZip       # build/distributions/mcd-windows.zip(Java 런타임 포함)과 .sha256
./gradlew test             # 단위 테스트: 소유권 프로토콜, 중계, 설정, GitHub 클라이언트
./gradlew paperTest        # 실제 Paper + Mineflayer 봇 E2E (느림)
./gradlew labTest          # 도커 실험실: 컨테이너마다 PC 하나, tailnet과 같은 포트로 실제 배포 구성 시나리오 (느림)
```

`paperTest`를 돌리려면 `nodes/_cache/paper-26.1.2-74.jar`가 있어야 하고 `e2e/`에서 `npm install`을 해 둬야 한다. 테스트 봇(Mineflayer)이 26.1까지만 접속할 수 있어서 봇 E2E는 26.1.2 월드로 돈다. 다른 Paper 빌드는 봇 없이 `./gradlew paperTest --tests '*PaperCompatibilityTest*' -Dmcd.paperBuild=<빌드>`로 확인한다(mcd가 기대는 콘솔 동작, 26.1.2 월드의 업그레이드). tailnet 시나리오는 조정 서버가 있을 때만 돈다(`MCD_TEST_CONTROL_URL`, `MCD_TEST_AUTH_KEY`, 개발 중에는 Headscale을 썼다). `labTest`는 Docker와 Go가 있어야 하고 `paperTest`와 같은 Paper jar와 `e2e/node_modules`를 쓴다. 노드마다 Mojang jar를 받으므로 인터넷이 필요하다. 버전 혼합 시나리오의 옛 버전은 `-Plab.oldRef=<커밋>`으로 바꾼다(기본은 직전 릴리스). 테스트 구성은 [docs/ARCHITECTURE.md의 테스트 전략](docs/ARCHITECTURE.md#11-테스트-전략)을 참고한다.

```text
src/main/java/mcd/
  cli/      CLI (init, play)
  gui/      GUI(메인 창, 설정, 월드 추가)
  node/     한 PC의 노드: 중계, 라우팅, 호스트 기간 관리, 이관
  lock/     git push를 락으로 쓰는 소유권 프로토콜
  net/      로컬 중계, tailnet 보조 프로그램 연동
  server/   Paper 프로세스 제어, 고정 빌드 다운로드
  world/    월드 repo 생성과 초기 파일
net-helper/ tailnet 보조 프로그램 mcd-net (Go, tsnet)
e2e/        테스트용 헤드리스 플레이어 (Mineflayer)
experiments/ 실험 기록 (E1′ ~ E9)
```

## 알려진 한계

- health를 지원하는 호스트는 장애 의심 후 조기 인수를 시도한다. 상태 확인과 인수 대기 외에 Git 통신·Paper 기동 시간이 더 필요하다. 로컬 두 노드 시험 두 번에서는 종료 후 재접속 완료까지 약 56초·74초였다. 실제 VPN의 시간 상한을 보장하지 않는다.
- writer가 Git 소유권을 20초 동안 확인하지 못하면 서버를 내린다. Git 장애 중에도 계속 플레이하는 대신 빠른 인수 시 기존 writer를 멈추기 위한 동작이다. 임의의 OS/VM 정지·절전 복귀까지 Paper 동시 실행이 절대로 없다고 보장하지 않는다.
- 장애 후에는 재접속해야 한다. 마지막 스냅샷 이후 최대 10분의 진행은 공유되지 않았을 수 있으며, PC가 돌아오면 남은 로컬 변경을 recovery 브랜치로 보존한다.
- 호스트를 넘길 때 나가는 PC의 플레이어도 같이 끊긴다. 넘기는 동안(5~8초) 남은 플레이어는 움직이거나 블록을 다루지 못하게 얼려 둔다(날기는 막지 못하지만 그동안의 이동은 넘어가지 않는다).
- 초대 코드(deploy key)를 가진 사람은 누구나 월드를 읽고 쓸 수 있고, 한 사람만 골라서 내보낼 수 없다(키를 바꾸고 모두에게 새 코드를 보낸다). 여러 사람이 deploy key 하나를 함께 쓰는 것은 GitHub가 뚜렷이 다루지 않는 쓰임새다.
- deploy key(SSH)는 git 명령마다 연결을 새로 맺어서 토큰(https)보다 push가 1초쯤 느리고, 호스트 이관이 몇 초 길어진다.
- tailnet 인증 키는 월드 repo에 들어가므로 초대받은 사람에게 보인다. GitHub 토큰과 deploy key는 설정 파일에 평문으로 저장된다.
- tailnet으로 들어온 플레이어는 서버에서 127.0.0.1로 보인다(IP 차단 기능은 쓸 수 없다).
- 설치 파일(.msi)은 아직 없다(zip을 풀어서 쓴다). 자동 업데이트는 v0.2.0부터 들어 있어서, v0.1.0은 한 번 직접 바꿔야 한다.
- 자동 업데이트는 받은 파일을 GitHub 릴리스의 SHA-256으로 검증한다. 다운로드가 깨지지 않았는지만 보장하고, 코드 서명은 하지 않는다.
- 아직 실제 원격 친구 환경에서는 확인하지 않았다(같은 PC의 VM과 테스트 봇으로 확인). 정품 클라이언트로는 한 PC에서 접속, 정품 인증, 첫 기동 대기를 확인했다.
- GitHub 이용 정책에는 과도한 자동 활동 금지 조항이 있다. mcd는 push 빈도를 낮게 유지하지만, 혹시 모를 계정 제재가 메인 계정에 미치지 않도록 월드 전용 계정을 권한다.
